🏛Architecture & System Flow

XenChat follows the ASP.NET Core MVC pattern. The browser communicates over standard HTTP for page rendering, uses WebSockets (SignalR) for real-time events, and establishes direct WebRTC peer-to-peer media streams for audio/video calls.

ℹ️
Signaling vs. Media

SignalR is used only as a signaling channel (SDP + ICE) for WebRTC call setup. Actual audio/video travels directly peer-to-peer, bypassing the server entirely.

🔐Authentication & OTP Verification

📧

Two-Step Registration

6-digit OTP sent via MailKit SMTP with 5-minute expiry in a thread-safe in-memory store.

🍪

Cookie Sessions

Standard MVC navigation uses ASP.NET Core session cookies with idle timeout.

🔑

JWT Bearer

AJAX and SignalR connections authenticate with JWT tokens generated on login.

🌐

Google OAuth 2.0

One-click sign-in with auto-provisioning, profile sync, and Render-compatible callback URL.

Registration Flow

  1. Submit Registration Form

    User provides username, email, password at /Account/Signup.

  2. OTP Generated & Cached

    A 6-digit code stored in PendingSignupStore with 5-minute TTL.

  3. Email Dispatched

    HTML email with OTP sent via MailKit SMTP (EmailService).

  4. OTP Verified

    User submits code at /Account/Verify. Account committed with PBKDF2-hashed password.

💬Real-Time Messaging

⚡

Instant Delivery

Messages persisted to PostgreSQL then immediately broadcast via ChatHub.SendMessage.

📷

Media Messages

Images use [img]URL[/img]Caption syntax, rendering with click-to-enlarge lightbox.

🗑️

Message Deletion

Senders delete their own messages; SignalR notifies both peers to remove the DOM node.

✅

Read Receipts

Opening a conversation auto-marks all incoming messages as IsRead = true.

📹WebRTC Audio & Video Calling

Direct P2P media via the browser's RTCPeerConnection API using Google STUN (stun:stun.l.google.com:19302). SignalR acts purely as the signaling channel.

Call Lifecycle

StepSignalR MethodDirectionPurpose
1. InitiateCallUserCaller → CalleeTriggers incoming call popup + ringtone
2. AnswerAnswerCallCallee → CallerAccepts or declines the call
3. SDP OfferSendCallOfferCaller → CalleeExchanges WebRTC SDP session description
4. SDP AnswerSendCallAnswerCallee → CallerCompletes WebRTC handshake
5. ICE RelaySendIceCandidateBoth ↔Relays ICE network candidates
6. TerminateEndCallEither → BothCloses media tracks and resets UI
⚠️
STUN Only — No TURN Server

Calls may fail when both peers are behind symmetric NAT. For production, configure a TURN server (e.g., Twilio Network Traversal or coturn).

🚀Getting Started (Local Development)

Prerequisites

.NET 8.0 SDK
PostgreSQL (local or Neon)
Cloudinary account (free)
Gmail App Password (SMTP)

Setup Steps

  1. Clone the repository
    Bash
    git clone <repo-url>
cd XenChat
  2. Create your .env file
    .env
    DATABASE_URL=postgresql://user:pass@host/dbname?sslmode=require
Cloudinary__CloudName=your-cloud-name
Cloudinary__ApiKey=your-api-key
Cloudinary__ApiSecret=your-api-secret
  3. Restore & run
    Bash
    dotnet restore
dotnet run
  4. Open in browser

    Navigate to https://localhost:7197 or http://localhost:5248

Auto-Initialization

Program.cs auto-creates all tables and seeds default test accounts on first startup. No manual migration commands needed.

🐳Docker Containerization & Deployment

XenChat ships with an optimized multi-stage Dockerfile targeting port 8080 — compatible with Render, Railway, Fly.io, and Azure App Services.

Dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY ["XenChat.csproj", "./"]
RUN dotnet restore "XenChat.csproj"
COPY . .
RUN dotnet publish "XenChat.csproj" -c Release -o /app/publish /p:UseAppHost=false

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .
ENV ASPNETCORE_HTTP_PORTS=8080
EXPOSE 8080
ENTRYPOINT ["dotnet", "XenChat.dll"]

Build & Run

Bash
docker build -t xenchat:latest .

docker run -d -p 8080:8080 \
  -e DATABASE_URL="postgresql://user:pass@host/db?sslmode=require" \
  -e Cloudinary__CloudName="your_cloud_name" \
  -e Cloudinary__ApiKey="your_api_key" \
  -e Cloudinary__ApiSecret="your_api_secret" \
  --name xenchat-app xenchat:latest

Deploy to Render / Railway

  1. Connect your repository

    Link your GitHub repo as a new Web Service.

  2. Set build type to Docker

    The platform auto-detects the Dockerfile in the repo root.

  3. Set environment variables

    Add DATABASE_URL, Cloudinary__CloudName, Cloudinary__ApiKey, Cloudinary__ApiSecret in the dashboard.

  4. Deploy

    Port 8080 is exposed automatically. App goes live at your assigned subdomain.
